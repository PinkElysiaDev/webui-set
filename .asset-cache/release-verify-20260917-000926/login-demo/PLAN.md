# 花海登录 Demo · PNG 分层实现与验收

## 当前进度（2026-09-16）

仅开发独立 `login-demo`，不迁移到主项目，不修改登录接口或后端；密钥仍为本地 `123`。
当前路线是 **独立 PNG 配准 + three.js 网格风动**，不是 MMD，也不是完整角色参考的互斥九块切片。

承接此次修复时，工作区已经比研究计划向前推进了一步：生成器输出五份独立素材、八层、manifest v3，
但浏览器还只接受旧九层 v2，并使用硬编码的静态配置。因此构建虽然通过，实际角色已进入静态降级。
此次在保留已有未提交工作的基础上，按静态配准 → 风动 → 遮挡 → 回归顺序衔接。

| 阶段 | 实现与校验 |
|---|---|
| 静态配准 | 清除身体原有重复短发；保留脸颈与完整衣裙底图；前后发在共同头部基准下搭接；关闭头纱不产生头部孔洞 |
| 资源协议 | 生成器与加载器统一 v3，不依赖固定图层个数；独立 `fallback.json` 与最终导出图层合成的 `fallback.png` 配套 |
| 连接风动 | 发束方向连续权重、各部件根部固定区、分相位轻摆；固定饰件与头纱布料分开，取消全局横坐标锁定 |
| 花层遮挡 | 原始二维 alpha、渲染同构坐标换算、最大风偏移与采样余量；完整手部和衣裙裁切边界参与布局求解 |
| 降级与检查 | 覆盖不足隐藏角色并关闭星屑；状态报告具体原因；补充素材校验、浏览器尺寸矩阵和失败／重试检查 |

### 明确保留的边界

- 三层花海的 PNG、位置、比例、着色、风场和 shader 不改动；仅增加 CPU 侧覆盖数据。
- 不新增角色素材、补花或用透明横带掩盖裁切；不修改下载目录的原图。
- 窄屏允许发尾出屏，保留完整脸部和登录操作区；不能同时满足遮挡与可见空间时安全隐藏，不能谎报覆盖成功。
- 当前 **768×1024** 的居中表单布局会触发这一隐藏策略。这是明确的保守降级，不代表该尺寸已经通过“角色可见”的视觉验收。
- 无风、减少动态、静态备用图使用同一套配准、遮挡区域和摆位结果。

## 坐标、来源与图层

逻辑画布 `1280×720`，源图保持 `3840×2160`，生成密度 `1.5`。源锚点先换算到逻辑坐标，
每层显式记录 `sourceAnchor → anchor`、等比 `scale` 和 `angle`。原图尺寸相同不代表已对齐。

| 顺序 | 层 | 源素材 | 约束 |
|---|---|---|---|
| 1 | body | 角色本身.png | 脸颈、身体、手和衣裙固定；去除替换掉的短发外轮廓 |
| 2 | back-hair | 后发发片.png | 完整后发底图，头皮／颈后搭接区固定 |
| 3 | body-front | 角色本身.png | 同一配准下的脸颈／前臂遮挡关系 |
| 4 | front-hair | 前发发片.png | 只含头发，主要保持固定，末梢轻摆 |
| 5–6 | ribbon-upper / ribbon-lower | 头纱飘带.png | 按飘带轮廓提取，避免重复整个头纱 |
| 7–8 | veil / ornament | 头纱本体.png | 同一源图的布料与固定饰件分解，合成 alpha 不重复叠深 |

完整角色、完整头发、完整头纱及场景参考只用于人工配准和对照，不作为生产图层来源。
布局定义位于 `scripts/character-layout.mjs`。manifest 保存源文件散列、各层变换与边界、
固定半径、发束根／梢、风动参数、实际锚点、面部边界、连接区覆盖及遮挡条带。

生成器先验证非空图层、变换后边界、锚点和头皮／颈后连接，再写出结果。
静态备用图从**最终导出的纹理**重组，避免裁剪前的低 alpha 像素与运行时图层不一致。
`check:character` 对静态合成与备用图做逐字节比较，并输出无头纱、头部放大和遮挡区域预览。

## 风动约束

顶点到根部的向量沿 `root → tip` 投影，生成连续进度；再乘固定半径内为零的径向权重。
不再使用全角色共享的横坐标阈值。身体和饰件不参与位移；前发仅末端使用小幅度。
头纱的布料／饰件透明度过渡在半径 85–150 内完成，其风动固定半径为 175，搭接段不会被拉开。
后发、头纱、飘带分别设置相位，共享既有风场；指针对角色的额外阵风保持限幅。

## 花海覆盖与布局

1. 中景／前景加载时读取原始 alpha，建立保守最小／最大值金字塔，保留列内部的透明空洞。
2. CPU 使用与花层 shader 相同的 cover、shift、scale 和上下坐标方向。
3. 风动包络包含环境风和指针 wake：横向上界 `2.4 × amplitude`，纵向 `0.375 × amplitude`，
   乘对应区域最大 root/tip 权重；另包含纹理过滤足迹及 3 CSS px 安全距离。
4. 屏幕覆盖网格为 4 CSS px 单元。每个单元查询整个单元及安全包络的 alpha 下界，
   按 `1 - (1 - mid) × (1 - front)` 合成；要求所有必须隐藏区域的单元 alpha 均不低于 0.98。
5. 遮挡区域是身体真实 alpha 与手部轮廓交集、源衣裙裁切边变换后的保守条带；不要求自然发梢隐藏。
   屏幕外部分视为不可见，屏幕内不能仅靠指尖一个点通过。
6. 桌面从卡片右侧开始，先以 1 CSS px 步长寻找最小向下调整；若无法保留面部空间，再降低比例重试。
   面部同时避开表单、视口边缘和花层的最坏情况覆盖；桌面至少保留 24px 卡片间距。
7. 遮挡缓存只在尺寸、可用花层、角色配置变化时重建；卡片尺寸改变重新求解。没有逐帧 GPU 回读或角色追随花朵抖动。
8. 取消所有角色层的底部渐隐。无法满足覆盖时隐藏角色，登录仍可用；星屑仅在已通过覆盖、接触邻域有效且不与表单冲突时显示。

开发地址加 `?inspect` 后，`window.__loginDemo.snapshot()` 提供来源、配准、根部权重、最终摆位、
各区域覆盖率、未覆盖单元数、最小安全距离及失败原因。原 `occlusionActive` 已移除。
原有 `motion`、`character`、`part`、`layer`、`petals`、`contact` 开关保留；隐藏遮挡层会重新求解并可能隐藏角色。

## 重建与验收

素材放置参见 `scripts/fetch-assets.md`。

```powershell
npm.cmd run assets:character
npm.cmd run check:character
npm.cmd run build
npm.cmd run dev -- --host 127.0.0.1 --port 5180
```

另一个终端运行浏览器检查，可通过 `--playwright` 指向本机已有的 `playwright-core/index.mjs`，
不新增测试框架或运行时依赖；浏览器驱动需已安装 Chromium：

```powershell
npm.cmd run check:scene -- --playwright "本机/playwright-core/index.mjs"
```

- 尺寸：1280×720、1440×900、1920×1080、2560×1080、2560×1440、768×1024、390×844。
- 每个尺寸检查分层／静态备用、昼／夜、减少动态，以及面部边界和实际遮挡区域的渲染差异。
- 正常风与指针扰动合计至少 30 秒，验证固定连接不动、发尾有运动、摆位不抖动。
- 验证无效 manifest、缺少单层、缺少全部角色资源、缺少中前景、重试、空值／错误密钥／123 登录及转场。
- `--baseline-prefix .asset-cache/resume-flowers` 可与本次修改前冻结截图比较；比较排除 DOM 表单、切换按钮和资源提示覆盖区，不把 UI 状态变化算作花海变化。
- 结果在 `.asset-cache/character-check/` 与 `.asset-cache/scene-check/`；这些本机衍生素材与报告不入库。

### 本轮实测结果

- 素材生成、静态图逐字节一致性校验、TypeScript／Vite 构建通过。
- 28 组尺寸 × 昼夜 × 分层／备用检查通过：24 组展示角色，768×1024 的 4 组按约束隐藏；浏览器未记录页面运行错误。
- 七种尺寸的冻结花海基线在排除 DOM 覆盖区后像素差异为零。
- 必须隐藏区域对比“显示／隐藏角色”截图，最大通道差为 5/255，符合 alpha 下界 0.98 的保守约束。
- 30 秒风动检查中，固定根部截图差异为零，发尾／头纱有可辨识运动；角色摆位未随花层抖动。
- 资源缺失、静态降级、无效配置、重试恢复，以及无角色条件下的登录和正常转场均通过。

后续如继续改善 768×1024 的角色展示，应单独评估窄屏构图；不能撤销当前隐藏保护，
也不能以改花海或放宽手部／衣裙覆盖阈值换取“显示成功”。
